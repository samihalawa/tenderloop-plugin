Start with `playbook({limit: 4000})`. Read the complete rules by passing `next_offset` as `offset`, keeping `part` and setting `expected_version` to the returned version. Read the evidence part when it governs your decision. Identify the bidder, exact case or lot, authorized act and deadline. Resolve conflicting dates and statuses using the latest official notice or receipt. Complete the act once if it is still owed. For a filing, open and save the native receipt with the exact filed documents. Record and read back the verified result in the same run.

Work in this order and no wider than the task needs:

1. For daily work, use `today` to cover overdue, owed, unrouted and portal recheck items in scope. Read the totals and follow `pagination[section].next_offset` through each required section. Use `section: changed` for one row per changed case, keeping the returned `since` timestamp across pages. Use `news` for individual log entries when needed. A preview or clipped result gives partial coverage. Use the workspace timezone for deadlines.
2. Use `tracker_get` with `case_id`, `platform` and `lot` when needed. Use the ledger to locate the official record and verify the actual act on the portal. A request to recheck can be open even while the case status is still under review.
3. Open your own tab in the workspace's TenderLoop browser. Check for a signed-in account or authenticated record, then recover a failed login through a supported route for that portal. Where the workspace needs a browser connection, pair the [TenderLoop Chrome extension](https://tenderloop.eu/downloads/tenderloop-chrome.zip) with `chrome_pair`.
4. Use `tracker_log` once per act with an `idempotency_key`. Set `checked: true` after a fresh portal read and use the returned `checked_at` when reporting the check time. If the exact portal case or lot confirms no application and the ledger status has no supporting filing evidence, record `not_recorded` with the observed result. Preserve existing receipts and filing history. Leave inconclusive status unset and record the evidence and next actor. On `insufficient_scope`, reconnect the same TenderLoop workspace with the required permission, verify the live state, then retry the intended write.

For new tenders, check the whole relevant ledger for duplicates. `opportunity_add` saves live opportunities and `opportunity_take` claims saved lots. Send `ids` when resuming a known list. Follow the returned IDs and use `opportunity_release` for an accidental hold. Resolve each claimed lot with a filing and its receipt, a closure supported by the exact reason, or a recorded outstanding dependency with its next action. For after-offer responses, apply `tender-record-reviewer` to the exact action as the playbook directs.

## e-marchespublics.com (Dematis)

Use `platform_guide({platform: "dematis"})` for the workspace's access instructions. Verify the bidder shown in the signed-in **Espace entreprise**. For an account-wide application check, open these native views:

- [Mes dépôts](https://private.e-marchespublics.com/societe/index.php?rub=mes_marches&etat_p=all&date1=&date2=&motclef=&page=1&r=reponses) lists procedures with deposit activity. Reconcile all pages to the account's **Mes dépôts** counter, then open each case’s **Historique** and **Dépôts** where available.
- [Tous mes marchés](https://private.e-marchespublics.com/societe/index.php?rub=mes_marches&etat_p=all&date1=&date2=&motclef=&page=1&r=all) includes closed procedures under **Toutes**. Check cases missing from **Mes dépôts** for filing evidence in their histories. The portal removes procedures closed for more than one year from this view.
- [Centre de messagerie](https://private.e-marchespublics.com/societe/index.php?rub=centre_messagerie) and **Mes procédures spécifiques** hold case communications and follow-up stages. Match relevant notices and attachments to the exact case and lot. Read subsequent events before deciding which action is owed.
- [Mes alertes reçues](https://private.e-marchespublics.com/societe/index.php?rub=alertes_recues) is the prospecting feed. It covers the last 90 days and at most 500 notices. Count subscriber-only rows as listings and report which notice bodies were inaccessible. Use the published BOAMP, TED or buyer notice where an exact match is available.

Compare the cases and lots with `tracker_list` scoped to `all`, including known alternate references and records stored under another portal code. Keep candidature, offer, replacement and negotiation envelopes distinct. An alert, downloaded DCE, access to a deposit form, or a journal entry that a deposit started is insufficient proof of filing. Use the native acknowledgement and exact filing time for a missing TenderLoop entry. Keep existing receipts and later buyer decisions when updating a record. If the portal shows activity but the acknowledgement is missing, report that gap instead of creating a filing from the list row. For a requested download, preserve the actual acknowledgements, messages, attachments and available filed files under their case and lot with their native sources. Report the number of listed procedures, receipts opened, ledger matches and open gaps.

Complete the exact work you own before reporting. If the current task authorizes dispatch, give each case one owner and pass its exact scope, instructions and receipt requirement. Read back every assigned outcome before calling the run complete. Continue independent cases while resolving a real dependency. Report what the portal verified, the acts recorded, and the exact work still open. Complete the work before preparing a scheduled report.
